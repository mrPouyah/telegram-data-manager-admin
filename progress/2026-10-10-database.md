# 2026-10-10 — Database layer

## Added

- `src/telegram_manager/catalog_db.py`: database operations for owner activation, access requests and decisions, revocation, projects, categories, topic destinations, project permissions, published content, item allowlists, authorized search, and retrieval references.
- `src/telegram_manager/schema.sql`: a unique partial index preventing duplicate pending access requests.
- `src/telegram_manager/config.py` and `__main__.py`: `init-db` can now initialize SQLite without a bot token; `check-config` still validates all deployment settings.
- `tests/test_catalog_db.py`: integration tests using temporary SQLite databases for permissions, search, revocation, item restrictions, and atomic publication records.
- `data/telegram_manager.sqlite3`: initialized local SQLite database with schema version 1 and no actual user or project records. This runtime file is ignored by Git.
- `README.md`: updated setup and database-layer notes.

## Verified

- Eight unit/integration tests pass using the installed Python 3.13 interpreter.
- `python -m telegram_manager init-db` created the local database without a bot token.
- Publication records keep content, attachment, message, and initial search references together in one SQLite transaction.

## Current limits

- Telegram admin verification and chat interactions are not implemented yet. The caller must verify the configured owner through Telegram before activating them in the database.
- `record_publication` is designed to be called only after Telegram confirms delivery. Handling uncertain sends and recovery jobs belongs to the publishing step.
- No real user approvals, projects, files, or content have been inserted into the local database.
- Document text extraction and independent file-byte backup are not implemented.

Connect the Telegram bot and implement the owner verification and access-request/approval screens using this database layer.
